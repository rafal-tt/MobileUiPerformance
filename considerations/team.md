# Team

## Facts

| Fact | Detail |
| --- | --- |
| Size | **3** software engineers |
| Strengths | Deep **C#** and **.NET MAUI** experience |
| Attitude | Willing to learn **new technologies** when justified |

## Implications for decisioning

- Prefer solutions that leverage existing MAUI/.NET skills first where they can win (custom handlers, DrawnUI/Skia in-process, WebView/Blazor hybrids). Visual-tree reduction and list virtualization are **already done and insufficient** as the main strategy.
- Full app migration (Flutter/Avalonia/…) is **out of scope for now** — learning remains possible later; do not plan a rewrite under current scope ([options.md](options.md)).
- New stacks (Flutter module, large Avalonia/native rewrite, heavy web UI) are **viable to learn**, but must pay for themselves: clear perf win, bounded scope, and sustainable ownership with a three-person team.
- Avoid strategies that require a large permanent specialist split (e.g. full dual-platform native teams) unless product scope and hiring change.
- Training/ramp time is acceptable; “we only know MAUI” is **not** a hard veto when evidence favors another approach.
